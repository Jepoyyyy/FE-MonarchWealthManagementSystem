9. Recommendations & Best Practices

🎯 Key Testing Priorities

  1. Start with smoke tests: Authentication, data loading, and stat cards display (5 critical tests)
  2. Cover error states early: API failures are high-risk, test all 500/401/timeout scenarios
  3. Test role-based access thoroughly: User/admin redirects are security-critical
  4. Validate chart data transformations: Zero-padding logic and percentage calculations are error-prone
  5. Performance baseline in CI: Set 3s load time budget, fail builds that exceed it

9.1 Test Implementation Guidelines

Guideline Details
Use Playwright Pro templates Leverage /pw:generate with dashboard templates: data-loading.md, chart-rendering.md, realtime-updates.md
Mock API responses Use page.route() to intercept /api/v1/me/dashboard and test error states without backend dependency
Isolate tests with fixtures Use test.use({ storageState: 'user-auth.json' }) for authentication, reset DB state before each test
Use data-testid strategically Already present: dashboard-loading, dashboard-error, recommended-section, stat-card
Web-first assertions Always use expect(locator).toBeVisible(), never await locator.textContent() without expect wrapper
Avoid waitForTimeout Use expect(locator).toBeHidden() instead of await page.waitForTimeout(2000)

9.2 Known Risks & Mitigation

Risk Mitigation Strategy
Flaky chart rendering tests Recharts lazy-loads. Always wait for chart container with expect(chart).toBeVisible() before hovering
Race condition in useEffect redirect Admin→user redirect via useEffect can cause flash. Test with { replace: true } navigation and assert final URL
Toast notifications timing Sonner toasts auto-dismiss. Capture with await expect(page.getByRole('status')).toBeVisible() immediately after error trigger
Date formatting locale issues Dashboard uses 'en-GB' format. Mock Date in tests or use regex patterns instead of exact date strings
Zero-value edge cases Division by zero in P&L calculation. Test explicitly with totalCost: 0 mock data
